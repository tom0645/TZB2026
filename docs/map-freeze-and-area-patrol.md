# 近景切图、文字清晰度与区域警戒修复

## 问题与修改

网页切换覆盖、优先级和通行图时，原实现反复创建图层 Canvas 和 GPU 纹理；切换或重置场景时，旧地表 Primitive 被删除，但其材质纹理未完整销毁。现在低分辨率图层使用持久纹理原地更新，调色板与 Canvas 复用；场景切换及 Viewer 销毁时显式释放地表材质。

高倍近景还会逐段投影整张地图上所有规划路线，其中大量路线位于视野外。现在先通过相机视锥裁剪路线段，只投影可见部分；同时修正相机背后线段导致箭头剩余距离变为负数的问题，避免生成落在路线外的箭头。

三维文字原先与 WebGL 画布共用分辨率，小字容易受系统缩放和渲染像素预算影响。现在单位、目标、区域和线索文字采用 HTML 覆盖层，按浏览器原生屏幕像素显示；只在实际绘制后更新投影位置，复用节点，不新增独立动画循环。图层本身继续保持现有渲染分辨率预算，避免为文字清晰而成倍增加三维像素数。文字层不拦截点选、平移或右键旋转。

区域封控中，首轮侦察达到覆盖率后会完成；当敌机处置、残骸清理任务也结束时，原实现没有任务接替，己方平台进入空闲，虽然仿真时钟继续推进。网页场景现增加低优先级持续外围巡查；处置和补能任务可抽调平台，任务结束后空闲无人机自动补回巡查。无人车没有清理或补能任务时仍可在保障点待命。原 CLI 的有限六阶段任务闭环保留。

另外，路径跟踪因安全约束进入 `BLOCKED` 后，原逻辑可能不再规划。现在从当前位置重新规划；失败时使用退避间隔，防止逐帧规划占用计算资源。

## 敌机处置后的状态

单机捕获或多机迫降完成当帧，敌方空中实体将自身高度设为 0 米、速度设为 0，再更新态势快照。残骸阶段保持静止，仍按原来连续 30 秒的清理流程执行。API 从态势快照输出 `altitude` 和 `speed`，不绕过态势读取真值。

三维模型、详情窗、地面标记与高度引线同步落地。旧回放若仍带过期速度，已处置的空中目标在详情窗按 0 米/秒显示。友方无人机继续使用原来的 10 米显示约定，地图编号不显示海拔后缀。

## 验证与边界

- 独立区域封控仿真运行至 1700 秒，第一波处理空窗和全部敌机清理后，己方无人机继续巡查；处置抢占及补能任务保持独立分配，原 CLI 闭环测试通过。
- 导航测试验证受阻后重新规划，以及规划失败的退避间隔；敌机状态测试覆盖两条处置路径当帧归零、保持静止及原残骸清理。
- 2560×1500 窗口、DPR 1.5、约 24 倍近景、4 Hz 长轨迹更新，连续约 94 秒完成 360 次切图，未出现页面卡死或 WebGL 错误。动态图层纹理只创建一次并复用 452 次；地表和模型没有随切图重建。
- 同一压力场景中，视野外路线的投影次数由约 150 万降至约 4050；最大点击处理约 8.3 毫秒，主线程最大心跳间隔约 105 毫秒。
- 高清文字专项 8 组、完整三维交互 33 组通过，覆盖相机旋转、缩放、跟随、节点复用、二维切换及上下文恢复。

该压力测试使用 Edge SwiftShader 软件渲染，大窗口平均约 21 FPS；它验证长时间交互和资源复用，不代表所有硬件与视角恒定 60 FPS。本次没有在测试机上直接复现原截图的完整无响应弹窗，但确认并修复了纹理资源泄漏和近景重复投影两个实际问题。
