### 挑战杯项目技术方案与分工

> \[\!note\] 项目技术框架
世界模型（态势推演）\-异构协同（任务分解与分配）\-具身智能（执行）的三层串联架构，大模型作为交互接口

#### 世界模型

本质是能对世界的演化规律有所认识，据此进行推演、预测的态势认知引擎。在任务场景中起到对当前场景态势进行推衍，对决策的未来走向进行预测的作用
主要功能为：

1. 接收环境、目标、平台、障碍、通信、任务约束等信息；

2. 形成当前态势表示，例如风险场、目标概率图、通信质量图、平台状态图；

3. 对未来态势进行预测，例如目标可能运动方向、风险扩散趋势、任务失败概率、平台资源消耗；

4. 对不同决策方案进行推演，例如“如果派 UAV\-1 去搜索 A 区域，UGV\-1 去 B 点封控，未来 5 分钟效果如何”。

#### 异构协同层次任务网络

接收世界模型给出的态势、风险、预测结果，主要功能为：

1. 高层任务分解：
例如“协同搜救”拆成搜索、识别、投送、引导、救援、补能、撤离等子任务。

2. 任务依赖关系建模：
例如“无人车救援”依赖“无人机先发现目标”，“无人机持续搜索”依赖“无人车提供换电”。

3. 异构平台能力匹配：
UAV 擅长广域搜索、快速到达、投送；UGV 擅长地面救援、承载、补能、封控。

4. 多目标任务分配：
综合时间、距离、能耗、风险、通信质量、任务收益，决定哪个平台执行哪个任务。

5. 全局资源管理：
包括电量、载荷、备用电池、任务负载、通信链路、平台故障等。

#### 具身智能

智能体需要识别并理解环境，并在此基础上完成任务。智能体需要实现“感知\-认知\-行动”闭环，并且需要具有协作能力，共同完成路径规划、编队跟踪等任务。

1. 局部感知能力；

2. 局部环境理解能力；

3. 局部路径规划与避障能力；

4. 路径跟踪与运动控制能力；

5. 与其他平台协同执行任务的能力。

#### 大模型

作为人机混合智能交互层，承担自然语言任务理解、指令解析、态势解释、方案说明与人工干预入口；设计网页前端进行展示

#### 大小模型架构设计

> 主要是针对屈植所提到的大小模型联动问题进行讨论设计：在尽可能缩短任务链路闭合时间的情况下，大小模型应该如何联动？也就是大模型既需要完全理解任务、合理调度小模型，又不能一直思考浪费时间。

**基本原则**

1. **大模型负责低频决策，小模型负责高频执行**
大模型主要处理任务级决策，如任务理解、任务分解、模型选择、参数调整和策略解释；小模型负责具体算法计算和平台执行，如路径规划、任务分配、跟踪预测和避障控制。

2. **紧急事件不等待大模型**
对于电量过低、路径阻断、通信中断、目标短时丢失等确定性较强的事件，应由规则层和小模型直接触发应急处理，避免因等待大模型推理而延误响应。

3. **大模型输出结构化任务链路**
大模型不直接输出自然语言指令，而应输出可解析的结构化任务图，包括子任务序列、调用的小模型、输入参数、执行约束和监视条件。

4. **小模型直接驱动智能体执行**
小模型根据大模型给出的任务链路和参数完成具体计算，输出平台可执行的路径点、任务分配结果、搜索区域、会合点或重规划方案。

5. **人机交互只在关键节点介入**
指挥员可通过自然语言输入新事件、调整任务目标或修改约束条件。大模型根据人的干预重新生成或局部修改任务链路，而不是持续占用任务执行过程。

**三层闭环架构**

- **快速反应层：** 快速反应层用于处理确定性强、时间敏感的事件。该层不依赖大模型，而是通过规则库和小模型直接触发响应。例如无人机电量低于安全阈值——调用返航或换电会合点规划模型；

- **大模型任务编排层：** 大模型任务编排层用于处理复杂任务理解和多目标权衡问题。当人输入新的任务需求，或系统出现无法由规则层直接处理的复杂事件时，大模型介入。

- **小模型执行层：** 小模型执行层负责具体算法计算，并直接驱动无人平台执行任务。小模型包括任务分配模型、路径规划模型、搜索规划模型、目标跟踪模型、能源管理模型、通信评估模型和在线重规划模型等。模型执行过程应尽可能自动化和并行化。大模型生成任务链路后，小模型调度器根据任务图调用相应模型，并将结果转化为平台可执行指令。

**任务模板化**

针对典型场景预置任务模板，避免大模型每次从零开始规划。

- 搜救任务模板：搜索 → 发现 → 投送 → 换电 → 救援 → 撤回；

- 园区封控模板：发现 → 跟踪 → 预测 → 封控点生成 → 任务分配 → 围控 → 重规划；

- 边境巡护模板：巡逻 → 越界检测 → 跟踪 → 逃逸路径预测 → 拦控 → 通信中继。
