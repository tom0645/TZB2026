# 边境巡检场景：山区边境异构空地协同巡检与异常处置

## 1. 背景

某山区边境段地形复杂、道路稀疏、通信覆盖不稳定，传统固定摄像头与单一巡逻车辆难以实现连续、可靠的边境态势感知。日常巡检需完成边境线及重点区域周期性巡查，并对突发异常快速响应——围栏破损、疑似人员越界、可疑车辆靠近、通信节点失效等。

仅靠无人车巡检覆盖有限、响应慢；仅靠无人机巡检续航有限、难以完成近距离核查和长期驻留。异构空地协同将多旋翼无人机的快速广域感知与无人车的近距离核查、移动中继、无人机补能结合起来，形成可持续、可调度的边境巡检闭环。

本场景验证异构协同指控系统在边境巡检中的任务分解、动态调度、多源告警融合和异常处置能力。

## 2. 场景参数

### 2.1 任务区域

| 参数 | 值 |
| :--- | :--- |
| 区域大小 | 12 km × 12 km |
| 边境线长度 | 约 12 km，沿区域北侧展开 |
| 地形 | 山地林区、河谷沟壑、巡逻道路、固定哨点 |
| 基地位置 | (1, 1) 附近 |
| 通信 | 假设平台间通信正常 |
| 坐标系 | 平面笛卡尔，西南角 (0, 0) |

### 2.2 平台配置

| 平台 | 数量 | 挂载能力 | 说明 |
| :--- | :--- | :--- | :--- |
| UAV（多旋翼） | 4 | sensor, effector | 巡逻搜索 + 目标跟踪拦截 |
| UGV（无人车） | 2 | sensor, charger, maintenance | 地面核查 + 充电 + 维修 |

### 2.3 任务时限

120 min。

## 3. 目标实体

### 3.1 越境人员 — PersonTarget(role="intruder")

| 属性 | 说明 |
| :--- | :--- |
| 初始位置 | 边境线附近随机生成 |
| 移动速度 | 1~2 m/s，向任务区域纵深移动 |
| neutralized | 被 effector UAV 拦截处置后 → True |
| escaped | 离开任务区域 → 标记逃逸 |

### 3.2 可疑车辆 — VehicleTarget

| 属性 | 说明 |
| :--- | :--- |
| 初始位置 | 道路入口或区域边缘 |
| 移动速度 | 5~15 m/s，沿道路网络行驶 |
| neutralized | 被 effector UAV 拦截处置后 → True |
| escaped | 驶出任务区域 → 标记逃逸 |
| 行为 | 感知被跟踪时加速 |

### 3.3 设施异常 — FacilityTarget

| 属性 | 说明 |
| :--- | :--- |
| 位置 | 边境线或固定节点附近，静止 |
| facility_type | "fence" / "camera" / "comm_node" |
| repaired | UGV 或 UAV 携带 maintenance 在 5m 内停留 ≥60s → True |

每个实体在 `update()` 中感知周围平台，自主修改自身状态（neutralized / escaped / repaired）。

### 3.4 线索实体 — CueEntity

边境巡检场景中，固定哨点和围栏传感器提供模糊异常信息，走 CueEntity → ValueMap 热源 → 搜索优先级图的间接引导路径。线索不在场景初始化时预置，而是由 World 按时间线生成，`discovered` 标记复用态势层的传感器探测流程（与 TargetEntity 一致）。

| 线索示例 | source | 生成时刻 | 说明 |
| :--- | :--- | :--- | :--- |
| 围栏勾挂衣物 | "fixed_sensor" | T=5min（与入侵者同步出现） | 围栏破损处发现织物残留，表明有人翻越。discovered=False，需平台传感器探测发现。指向 person |
| 地面足迹 | "historical" | T=8min | UGV 巡逻路线附近的越境足迹，人已离开。discovered=False，需传感器探测。指向 person |
| 哨点红外告警 | "fixed_sensor" | T=10min | 固定红外探头捕捉热源移动，方向指向纵深。discovered=True，外部注入直接生效。指向 person |
| 人工情报 | "manual" | T=15min | 上级通报某区域可疑活动。discovered=True，外部注入直接生效。指向 vehicle |

> **物理发现**（discovered=False）：由态势层传感器探测标记，发现后注入 ValueMap。**外部注入**（discovered=True）：生成即生效，代表指控系统从外部渠道收到的情报。

## 4. 任务来源

本场景所有任务通过以下三种途径注入 TaskTracker：

| 来源 | 任务 | 触发条件 |
| :--- | :--- | :--- |
| **场景初始注入** | ReconTask（覆盖边境线 + 重点区域，覆盖率≥95%） | 场景启动时 |
| **决策系统生成** | InterceptTask | HostileTargetRule：发现越境人员或可疑车辆（discovered=True） |
| | RepairTask | FacilityAnomalyRule：发现设施异常（discovered=True 且 repaired=False） |
| | ChargeTask | LowBatteryRule：UAV 电量低于阈值（如 20%） |
| | ReconTask（缩小范围） | 搜索优先级图中出现高价值区域（哨点报告异常 → 线索热源注入后） |
| | ReconTask（恢复巡逻） | 覆盖新鲜度下降（侵蚀模型判定覆盖失效区域扩大）→ 重新生成以维持闭环 |
| **人工干预** | ArriveTask / OccupyTask 等 | 操作员手动指定 |

固定哨点或感知设备报告异常时，不直接生成任务，而是将线索注入 ValueMap（叠加高斯热源并随时间衰减），影响搜索优先级图。决策系统检测到边境线附近出现高优先级区域时，生成缩小范围的 ReconTask，引导 UAV 重点扫描该区域。

ReconTask 完成后若覆盖新鲜度因侵蚀模型下降，决策系统自动重新生成 ReconTask，维持边境巡检闭环。

## 5. 任务流程

### 阶段一：初始部署与巡检规划

- 场景启动时，TaskTracker 注入初始 ReconTask（边境线覆盖率≥95%）
- UAV 沿边境线和道路网络执行广域扫描
- UGV 沿巡逻道路向任务区域纵深移动，选择合适位置作为移动中继和换电节点
- 态势层持续更新覆盖图，覆盖新鲜度随侵蚀模型（max_speed=15 m/s）衰减
- World 按时间线在 T=5min 生成越境人员及围栏勾挂衣物线索，T=8min 生成地面足迹线索，T=10min 生成哨点红外告警（外部注入）

### 阶段二：线索驱动定向搜索

固定哨点和围栏传感器按预设时刻将线索生成到世界中，平台传感器探测到后通过 `situation.inject_entity()` 推入态势层。高斯热源随时间衰减，决策系统检测到边境线附近出现高优先级区域后，生成缩小范围的 ReconTask，引导 UAV 重点扫描该区域。

> 例：围栏传感器在坐标 (8000, 500) 附近检测到围栏破损且有织物残留 → CueEntity 注入 ValueMap，在破损位置生成半径 500m、置信度 0.7 的高斯热源 → 优先级图在该区域抬高 → 决策系统生成 ReconTask(area=栅栏破损周边 2km × 2km) → UAV 前往该区域精细搜索，发现越境人员。

### 阶段三：广域巡检与异常触发

UAV 和 UGV 持续巡检（覆盖初始 ReconTask 和线索驱动的 ReconTask），探测到异常后态势层标记 `discovered = True`，决策系统反应规则自动生成对应任务：

| 异常类型 | 决策规则 | 生成任务 |
| :--- | :--- | :--- |
| 发现越境人员 | HostileTargetRule | InterceptTask（required_capabilities=["effector"]） |
| 发现可疑车辆 | HostileTargetRule | InterceptTask（required_capabilities=["effector"]） |
| 发现设施异常 | FacilityAnomalyRule | RepairTask（required_capabilities=["maintenance"]） |

### 阶段四：协同确认与处置

- UAV 携带 effector 能力跟踪目标，进入处置距离 → 目标自身 `neutralized = True`
- InterceptTask 完成（check_field="neutralized", check_value=True）
- UGV 沿道路向异常点或最近可达核查点移动
- 多起异常并发时，决策系统根据优先级（移动目标 > 固定设施）和平台状态动态分配

### 阶段五：设施维修

- UGV（携带 maintenance）行驶至 FacilityTarget 5m 内停留 ≥60s
- FacilityTarget 在 `update()` 中检测到 maintenance 平台 → 自身 `repaired = True`
- RepairTask 完成（check_field="repaired", check_value=True）

### 阶段六：任务恢复与巡检闭环

- 异常处置完成后，对应 InterceptTask / RepairTask 完成
- 决策系统检查覆盖新鲜度，若边境线覆盖因处置任务导致下降，自动重新生成 ReconTask
- UAV 电量不足时 → LowBatteryRule 触发，生成 ChargeTask → UAV 降落 UGV 换电（UGV 消耗一块备用电池，耗时 5min）
- 任务结束时效能评估器输出完整巡检报告

## 6. 评价指标

| 指标 | 说明 |
| :--- | :--- |
| 边境线覆盖率 | 任务时间内被有效巡检的边境线长度占比 |
| 异常处置成功率 | 完成核查/拦截/修复的异常事件占真实异常的比例 |
| 平均响应时间 | 从异常触发到首平台到达的时间 |
| 移动目标跟踪连续性 | 越境人员/车辆被持续观测的时间比例 |
| 目标逃逸次数 | 人员或车辆成功逃出任务区域的次数 |
| 超时处置数量 | 超过规定时限仍未处置的事件数量 |
| 协同效能增益 | 对比无充电中继、无多平台协同的基准方案 |

## 7. 场景验证重点

- 异构平台协同巡检（UAV 广域覆盖 + UGV 地面核查 + 充电补能）
- 线索经 ValueMap 间接引导搜索（围栏勾挂衣物等 CueEntity → ValueMap 热源 → 优先级图倾斜 → 决策系统生成 ReconTask）
- 基于事件动态重规划（多异常并发时的优先级排序与资源分配）
- 决策系统反应规则的自动触发（HostileTargetRule / FacilityAnomalyRule）
- 实体自主状态变更（PersonTarget/VehicleTarget 感知 effector → neutralized；FacilityTarget 感知 maintenance → repaired）
- 持续巡检闭环能力（覆盖新鲜度下降 → 自动重新生成 ReconTask）
