# 搜救场景：荒野多人失踪异构空地协同搜救

## 1. 背景

某自然保护区发生多人徒步走散失联事件。失踪人员共5名，分散于约10 km × 10 km的荒野区域内。该区域地形起伏，间有稀疏林地和干涸沟壑，无既有道路。部分人员可能受伤，可安全等待救援的时间缩短。救援窗口受人员生命体征和夜间来临双重限制，需在最短时间内完成搜索与可靠救援。

单一无人系统难以同时满足大范围搜索和实质性救助需求。多旋翼无人机可快速覆盖广阔区域并精准定位目标，但续航有限、无法承载人员转运，仅能投送急救物资。无人车具备载人救助和能源补给能力，但视野狭窄、行进速度慢，难以独立完成大范围寻人。异构空地协同将空中广域感知、快速物资投送与地面实质性救援、持续能源保障深度融合，方可高效达成搜救目标。

本场景检验异构协同指控系统的任务规划、资源调度、多源信息融合与动态协同能力。

## 2. 场景参数

### 2.1 任务区域

| 参数   | 值                   |
| :--- | :------------------ |
| 区域大小 | 10 km × 10 km       |
| 地形   | 起伏荒野，稀疏林地，干涸沟壑      |
| 坐标系  | 平面笛卡尔，西南角 (0,0) 为基地 |
| 通信   | 假设平台间通信正常           |

### 2.2 平台配置

| 平台       | 数量 | 挂载能力                   | 说明           |
| :------- | :- | :--------------------- | :----------- |
| UAV（多旋翼） | 4  | sensor, medical        | 广域搜索 + 急救包投送 |
| UGV（无人车） | 2  | sensor, charger, cargo | 移动充电站 + 人员救援 |

### 2.3 任务时限

120 min。

## 3. 目标实体：失踪人员

5名失踪人员独立随机分布于任务区域内（排除不可到达的陡崖区）。每名人员为 `PersonTarget(role="victim")`：

| 属性               | 说明                                                             |
| :--------------- | :------------------------------------------------------------- |
| survival\_time   | 初始 \[120, 300] min 均匀分布，持续消耗                                   |
| injured          | 随机2名标记为受伤，消耗速率×2                                               |
| received\_supply | UAV 在 2m 内投送急救包后 → True，injured → False，survival\_time +120min |
| rescued          | UGV 在 2m 内停留 ≥30s 后 → True，生存时间冻结                              |

**失败判定**：任一人员 survival\_time ≤ 0 则视为错过救援窗口。

实体在每个 `update()` 中：

1. 消耗 survival\_time（受伤者2倍速）
2. 查询 `sim_manager.get_platforms_in_range(pos, 2.0)`，感知医疗投送和救援动作
3. 自主修改 injured / rescued / received\_supply

## 4. 任务来源

本场景所有任务通过以下三种途径注入 TaskTracker：

| 来源         | 任务                                                             | 触发条件                                                                       |
| :--------- | :------------------------------------------------------------- | :------------------------------------------------------------------------- |
| **场景初始注入** | ReconTask（覆盖任务区域，覆盖率≥90%）                                      | 场景启动时                                                                      |
| <br />     | DiscoverTask（target\_entity\_type="person", required\_count=5） | 场景启动时                                                                      |
| **决策系统生成** | MedicalDeliveryTask                                            | PersonDiscoveredRule：发现受伤人员（discovered=True 且 injured=True）                |
| <br />     | RescueTask                                                     | PersonDiscoveredRule：发现未受伤人员；或 InjuryHandledRule：受伤人员完成医疗投送（injured→False） |
| <br />     | ChargeTask                                                     | LowBatteryRule：UAV 电量低于阈值（如 20%）                                           |
| <br />     | ReconTask（缩小范围）                                                | 搜索优先级图中出现高价值区域（线索热源注入后）                                                    |
| **人工干预**   | ArriveTask / OccupyTask 等                                      | 操作员手动指定                                                                    |

线索实体（CueEntity）不直接生成任务。线索由固定感知节点或人工报告注入 ValueMap（叠加高斯热源并随时间衰减），影响搜索优先级图。决策系统检测到高优先级区域时，生成缩小范围的 ReconTask。

## 5. 任务流程

### 阶段一：初始部署与广域搜索

- 场景启动时，TaskTracker 注入初始 ReconTask 和 DiscoverTask(type="person", count=5)
- UGV 携载 UAV 及备用电池、急救包从基地出发，向区域纵深预判有利位置行驶
- UAV 挂载急救包升空，按搜索优先级图执行广域扫描
- 若启用线索机制，线索注入 ValueMap 热源 → 搜索优先级图倾斜 → 决策系统生成缩小范围的 ReconTask

### 阶段二：发现人员 — 反应规则序贯触发

UAV 探测到人员后，态势层标记 `discovered = True`：

- 每发现一人，DiscoverTask 计数 +1；全部 5 人 discovered 后 DiscoverTask 完成
- **PersonDiscoveredRule** 检查人员状态：
  - 若 **injured=True**：生成 MedicalDeliveryTask（required\_capabilities=\["medical"]）
  - 若 **injured=False**：生成 RescueTask（required\_capabilities=\["cargo"]）

MedicalDeliveryTask 完成后（人员 injured → False），**InjuryHandledRule** 自动生成 RescueTask。

**序贯任务链示例**：

```
DiscoverTask(type="person", count=5)         【场景初始注入 — 聚合任务】
  PersonDiscoveredRule 每发现一人触发一次：

  受伤人员 #101：
    → MedicalDeliveryTask(#101)               【决策系统生成】
      → 完成（injured=False）
        → RescueTask(#101)                    【决策系统生成】
          → 完成（rescued=True）

  未受伤人员 #102：
    → RescueTask(#102)                        【决策系统生成】
      → 完成（rescued=True）
```

### 阶段三：能源接力与持续覆盖

- UAV 电量接近临界值 → **LowBatteryRule** 触发，生成 ChargeTask
- 决策系统规划 UAV 与 UGV 会合点，下达 ChargeTask
- UAV 降落在 UGV 顶部平台，UGV `ChargerCapability.on_use()` → battery\_stock--，UAV `battery = max_battery`（耗时 5min）
- 换电完成后 UAV 升空继续搜索，突破单架无人机半径限制

### 阶段四：协同救援

- UGV 根据人员坐标和实时态势，规划可通行救援路径
- UAV 悬停监视人员周围环境，为 UGV 预警地形障碍
- UGV 行驶至人员 2m 内停留 ≥30s → PersonTarget 自身 `rescued = True`
- RescueTask 完成，UGV 继续前往下一目标

### 阶段五：撤回与终止

- 全部获救人员登车后 UGV 返回基地
- 任务时限耗尽或所有人员 survival\_time 归零 → 仿真终止
- 效能评估器检查全局目标：成功救援人数 ≥ 4

## 6. 评价指标

| 指标                | 说明                       |
| :---------------- | :----------------------- |
| 成功救援人数 (N\_saved) | UGV 完成救援并返回基地的人员总数，越高越好  |
| 任务完成时间 (T\_total) | 最后一名人员成功上车并返回基地的时间       |
| 人均搜索发现时间          | 从任务开始到首次发现各人员的平均时间       |
| UAV 总搜救效率         | 单位能耗下的有效搜索覆盖面积与成功投送次数    |
| 医疗投送及时性           | 受伤人员从被发现到收到急救包的时间，越短越好   |
| 协同效能增益            | 对比无投送增益、无移动充电、仅单一平台的基准方案 |

## 7. 场景验证重点

- 动态任务分配与序贯任务链执行（Discover → MedicalDelivery → Rescue）
- 决策系统反应规则的自动序贯触发（PersonDiscoveredRule → InjuryHandledRule）
- 多平台能源管理（UAV-UGV 会合换电，LowBatteryRule 自动生成 ChargeTask）
- 不确定条件下的路径规划（UGV 在无道路地形中向人员坐标行进）
- 急救包库存管理与投送决策
- 线索经 ValueMap 间接引导搜索（非直接生成任务）
