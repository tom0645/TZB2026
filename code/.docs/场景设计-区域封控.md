# 区域封控场景：机场周边重点区域反无人机协同防控

## 1. 背景

某民用机场周边出现非合作无人机异常活动。机场围界及跑道净空区属于低空安全重点防护区域，净空保护高度 500 m。若非合作无人机进入跑道净空区或围界上空，可能对机场起降秩序和空域运行安全造成影响。需在不干扰正常航班运行的前提下，快速完成非合作无人机的发现、识别、跟踪、封控与安全处置。

单一反无手段难以满足机场周边低空防护的多重需求。固定感知设备提供初始告警和粗略方位，但受遮挡和部署位置限制无法持续覆盖全部低空区域；单架无人机具备机动追踪能力，但在多目标和机场运行约束下难以独立完成合围压制和安全处置；无人车具备围界道路巡逻、移动中继和残骸清理能力，但无法独立完成空中目标快速跟踪。

异构空地协同将固定节点粗告警、多无人机协同跟踪合围、无人车地面封控和残骸清理结合起来，形成完整的低空防控闭环。本场景检验指控系统在重点区域低空防控中的任务规划、资源调度、协同封控、在线重规划和安全约束处理能力。

## 2. 场景参数

### 2.1 任务区域

| 参数 | 值 |
| :--- | :--- |
| 区域大小 | 6 km × 6 km |
| 坐标系 | 平面笛卡尔 |
| 区域划分 | 外围预警区 → 围界管控区 → 核心禁入区（净空 500m） |

三层区域仅作为参数化约束，更换为园区、能源设施或重大活动区域时，可通过调整核心区边界和禁入高度复用同一框架。

### 2.2 平台配置

| 平台 | 数量 | 挂载能力 | 说明 |
| :--- | :--- | :--- | :--- |
| UAV（多旋翼） | 5 | sensor, effector | 搜索 + 跟踪 + 合围 + 处置 |
| UGV（无人车） | 2 | sensor, charger, debris_clear | 围界巡逻 + 残骸清理 |

UAV 统一为同型号多旋翼，通过指控系统分配不同任务来扮演搜索、跟踪、合围或处置角色，不按型号区分。

### 2.3 任务时限

90 min。

## 3. 目标实体：非合作无人机

入侵目标为 `AerialTarget`，分两波：

### 第一波

1 架黑飞从机场外围低空进入，试图接近围界或跑道净空区。验证单目标快速发现、跟踪、处置的完整闭环。

### 第二波

3~5 架小型非合作无人机从不同方向或分批进入。验证多目标任务优先级排序和在线重规划能力。

### 实体行为

| 属性 | 说明 |
| :--- | :--- |
| 飞行速度 | 8~18 m/s |
| 飞行高度 | 30~200 m |
| 机动方式 | 直线接近 → 被跟踪 >5s 时转向/加速/变高 |
| neutralized | 两种路径由实体自身判断 ↓ |

**处置路径一（单机捕获）**：AerialTarget 在 `update()` 中检测到 effector UAV 进入 15m 且持续锁定 ≥5s → `neutralized = True`，平台 `EffectorCapability.on_use()` → charges--。

**处置路径二（多机合围迫降）**：AerialTarget 检测到 ≥3 架 UAV 从不同方向（方位角差异 ≥60°）持续压制 ≥10s → `neutralized = True`。

neutralized 后目标坠落地面成为残骸，AerialTarget 自身变为地面静态实体（altitude=0），由携带 debris_clear 能力的 UGV 前往清理。

### 实体行为补充：残骸清理

neutralized 后，AerialTarget 在 `update()` 中：
- 坠落至地面，位置不再改变
- 感知周围平台：查询 `sim_manager.get_platforms_in_range(self.position, 10.0)`
- 若有携带 debris_clear 能力的 UGV 在 10m 内停留 ≥30s：
  - 自身 `debris_cleared = True`，`enabled = False`

## 4. 任务来源

本场景所有任务通过以下三种途径注入 TaskTracker：

| 来源 | 任务 | 触发条件 |
| :--- | :--- | :--- |
| **场景初始注入** | ReconTask（覆盖外围预警区，覆盖率≥90%） | 场景启动时 |
| **决策系统生成** | InterceptTask | HostileTargetRule：发现黑飞目标（discovered=True） |
| | ClearTask（残骸清理） | LandingSiteRule：黑飞 neutralized=True 且 debris_cleared=False |
| | ChargeTask | LowBatteryRule：UAV 电量低于阈值（如 20%） |
| | ReconTask（缩小范围） | 搜索优先级图中出现高价值区域（固定感知节点粗告警 → 线索热源注入后） |
| **人工干预** | ArriveTask / OccupyTask 等 | 操作员手动指定 |

说明：
- **InterceptTask** 的 `required_platforms` 设为 1（最少 1 架 effector UAV 即可启动）。决策系统根据可用平台数量尽量多分配，以支持合围路径。实体（AerialTarget）自主选择处置路径：有 1 架 effector UAV 进入 15m 则走捕获路径，有 ≥3 架从不同方向压制则走合围路径，两者同时满足则任一先达成即生效。
- 固定感知节点推送粗告警时，不直接生成任务，而是将线索注入 ValueMap（在预警区对应方向叠加高斯热源并随时间衰减），影响搜索优先级图。决策系统检测到高优先级区域时，生成缩小范围的 ReconTask。

## 5. 任务流程

### 阶段一：粗告警接收与初始部署

- 场景启动时，TaskTracker 注入初始 ReconTask（覆盖外围预警区）
- UAV 携带 sensor + effector 升空进入待命空域
- UGV 沿围界道路向可能处置区域前移
- 固定感知节点推送粗告警（方位角范围 + 距离范围 + 置信度）→ 注入 ValueMap 热源 → 搜索优先级图倾斜 → 决策系统生成缩小范围的 ReconTask

### 阶段二：目标搜索与确认

- UAV 按搜索优先级图（外围高价值、中心低价值）执行搜索
- 态势层发现黑飞目标 → `discovered = True`
- **HostileTargetRule** 触发，生成 InterceptTask（required_platforms=1, required_capabilities=["effector"]）
- 决策系统为 InterceptTask 分配 UAV：优先在目标通往核心禁入区的方向形成阻断态势

### 阶段三：协同跟踪、合围与处置

- 指控系统为 InterceptTask 分配多架 UAV：部分负责跟踪，部分负责侧向合围
- AerialTarget 在 `update()` 中感知周围 effector UAV，自主判定 neutralized：
  - 1 架 effector UAV 进入 15m 锁定 ≥5s → neutralized（捕获）
  - ≥3 架 UAV 不同方向（方位角差 ≥60°）持续 ≥10s → neutralized（合围迫降）
- InterceptTask 完成（check_field="neutralized", check_value=True）

### 阶段四：残骸清理

- neutralized 后 AerialTarget 坠落地面成为残骸（altitude=0，位置固定）
- **LandingSiteRule** 检测到 neutralized=True 且 debris_cleared=False → 生成 ClearTask（required_capabilities=["debris_clear"]）
- UGV 携带 debris_clear 能力前往残骸位置，进入 10m 内停留 ≥30s
- AerialTarget 感知到携带 debris_clear 能力的 UGV → 自身 `debris_cleared = True`
- ClearTask 完成（check_field="debris_cleared", check_value=True）
- 残骸清理确保跑道/围界安全，消除 FOD（外来物损伤）风险

### 阶段五：在线重规划

场景设置有限动态事件，验证重规划能力：

| 事件 | 实体行为变化 | 决策系统响应 |
| :--- | :--- | :--- |
| 第一波目标突然转向 | AerialTarget 改变飞行方向和速度 | 态势层检测到轨迹偏离 → 决策系统更新 InterceptTask 平台分配（调整合围位置） |
| 第二波多目标出现 | 新 AerialTarget 实体生成并进入区域 | UAV 探测到新目标 → HostileTargetRule 为每个目标生成 InterceptTask → 决策系统按距核心区距离和速度排序优先级，重新分配平台 |
| 围界道路临时受限 | 可通行图更新 | 决策系统为 UGV 重规划可通行路线 |

### 阶段六：终止与评估

- 所有非合作无人机被 neutralized 或任务时限耗尽 → 仿真终止
- 效能评估器检查全局目标：核心区入侵次数 = 0
- 若任一黑飞进入核心禁入区 → 判定失败

## 6. 评价指标

### 协同类

| 指标 | 说明 |
| :--- | :--- |
| 任务分配耗时 | 目标确认到任务分配完成的时间 |
| 合围形成时间 | 目标判定高风险到多 UAV 形成有效合围的时间 |
| 目标持续跟踪率 | 目标被有效观测的时间占比 |
| 协同处置成功率 | neutralized 目标数 / 目标总数 |
| 在线重规划耗时 | 动态事件后生成新分配方案的时间 |

### 安全类

| 指标 | 说明 |
| :--- | :--- |
| 核心区入侵阻断率 | 未进入核心禁入区的目标占比 |
| 风险收敛时间 | 首次告警到所有目标解除风险的时间 |
| 安全处置比例 | 在安全区域完成处置的目标占比 |
| 残骸清理完成率 | debris_cleared 目标数 / neutralized 目标总数 |
| 己方平台违规次数 | UAV 误入核心净空区的次数 |

## 7. 场景验证重点

- 粗告警线索经 ValueMap 引导快速搜索与目标确认（非直接生成任务）
- 多 UAV 协同跟踪、合围和处置（实体自主判定 neutralized，决策系统生成 InterceptTask）
- 实体双路径处置：单机 effector 捕获 或 多机合围迫降
- UGV 参与围界巡逻、移动中继和残骸清理的空地协同
- 多目标条件下的任务优先级排序与在线重规划
- 机场运行安全约束下的处置决策（不将目标驱赶至跑道方向）
